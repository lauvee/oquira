# Product Roadmap

The roadmap is exploratory and will evolve as research and implementation progress.

## Phase 1 — Discovery

- Research Open Banking and Open Finance concepts.
- Understand relevant international frameworks.
- Research the Dominican Republic landscape.
- Identify actors, use cases, and potential constraints.
- Define initial product requirements.

### Discovery exit criteria

- Identify relevant ecosystem actors and their roles.
- Document priority use cases and user needs.
- Identify known regulatory, technical, and operational constraints.
- Define initial functional and non-functional requirements.
- Document assumptions that require further validation.

## Phase 2 — Architecture and design

- Define the domain model.
- Design the modular monolith architecture.
- Define API contracts.
- Design identity, authorization, and consent workflows.
- Prepare initial user experience flows.

## Phase 3 — MVP

- Implement user authentication.
- Simulate financial institutions.
- Connect a simulated institution.
- Request and authorize data-sharing consent.
- Display accounts, balances, and transactions.
- Allow consent revocation.

## Phase 4 — Developer experience

- Publish API documentation.
- Provide examples and integration guides.
- Improve observability and auditability.

## Phase 5 — Experimentation

- Explore AI-assisted transaction categorization.
- Evaluate LLM-based financial data explanations.
- Experiment with retrieval-augmented generation.
- Evaluate privacy, safety, and reliability.

## Guiding principle

Build incrementally. Validate assumptions before introducing additional infrastructure or complexity.

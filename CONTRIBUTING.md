# Contributing to Oquira

Thank you for your interest in contributing to Oquira!

Oquira is an open-source project exploring Open Finance, with an initial focus on the Dominican Republic. Contributions that improve its documentation, architecture, security, developer experience, and educational value are welcome.

## Project Principles

Please keep the following principles in mind when contributing:

- Open source and transparency.
- Security and privacy by design.
- Synthetic data only; never use real banking credentials or sensitive financial information.
- Clear documentation and maintainable code.
- Standards-oriented and interoperable architecture.
- Practical, incremental development.

## Before Contributing

1. Read the project README and relevant documentation.
2. Check existing issues and pull requests to avoid duplicated work.
3. For significant changes, open an issue first to discuss the proposal.
4. Make sure your contribution aligns with the project's current scope and roadmap.

## Development Workflow

1. Fork the repository.
2. Create a descriptive branch from `main`.
3. Make focused changes.
4. Add or update tests when applicable.
5. Update documentation when behavior or architecture changes.
6. Run the relevant checks locally.
7. Submit a pull request against `main`.

Suggested branch naming:

- `feature/short-description`
- `fix/short-description`
- `docs/short-description`
- `refactor/short-description`

## Pull Request Guidelines

Please ensure that your pull request:

- Has a clear and descriptive title.
- Explains the problem and proposed solution.
- References related issues when applicable.
- Includes tests or explains why tests are not applicable.
- Does not introduce real financial data, credentials, secrets, or private information.
- Keeps changes focused and reasonably scoped.

## Code and Documentation Standards

- Prefer readable, maintainable, and well-documented code.
- Follow the conventions already established in each component.
- Avoid introducing unnecessary dependencies.
- Document significant architectural decisions.
- Do not claim integration with real financial institutions unless such integration has been explicitly implemented and verified.

## Security

If you discover a potential security vulnerability, do not disclose it publicly in an issue or pull request.

Please follow the instructions in [SECURITY.md](SECURITY.md).

## Community Standards

All contributors are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Questions
